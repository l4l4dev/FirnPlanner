保存先は​どこですか​? Markdown を​他の​エディタで​開いても​よいですか​?Where are my files stored? Can I open the Markdown files in another editor?

既定の​保存先は​ ~/Documents/FirnPlanner です (設定​「ファイル」で​変更できます)。​日ごとの​ファイルは​ Daily/年/月/年-月-日.md (例: Daily/2026/09/2026-09-01.md)、​Inbox は​保存先ルート直下の​ Inbox.md、​繰り返しタスクの​定義は​同じく​ Recurring.md に​保存されます。​どれも​普通の​ Markdown ファイルなので、​他の​テキストエディタや​ AI ツールで​開いて​読み​書きしてかまいません。 By default your files are stored under ~/Documents/FirnPlanner (you can change this in Settings > Files). Each day is one file at Daily/YYYY/MM/YYYY-MM-DD.md (e.g. Daily/2026/09/2026-09-01.md), the Inbox is Inbox.md at the root of that folder, and recurring task definitions live in Recurring.md. These are all plain Markdown files, so it is fine to open and edit them with another text editor or an AI tool.

オフラインで​使えますか​?Does it work offline?

はい、​使えます。​FirnPlanner は​ローカルの​ファイルだけで​動き、​開発者の​サーバーは​ありません。​ネットワークを​使うのは​次の​場合だけです: 設定で​ Google カレンダー連携を​オンに​している​ときの​予定の​読み取り、​本文に​貼った​リモート画像の​1回だけの​取り込み、​新しい​版が​ないかの​確認、​匿名の​使用状況の​送信 (内容は​含みません。​詳しくは​プライバシーポリシーを​ご覧ください)。​これら​以外の​操作に​通信は​発生しません。 Yes. FirnPlanner works entirely with local files, and there is no server run by the developer. The only cases where it uses the network are: reading your events when Google Calendar integration is turned on in Settings, a one-time download when you paste a remote image URL into your notes, checking for a new version, and sending anonymous usage statistics (never the content you write — see the privacy policy for details). Nothing else touches the network.

動作環境は​?What are the system requirements?

macOS 26 以降が​必要です。 macOS 26 or later is required.

うっかり消してしまった​内容は​戻せますか​?Can I recover content I accidentally deleted?

アプリ内の​取り消し (⌘Z) は、​その場で​編集していた​範囲に​効きます。​ファイルは​普通の​ Markdown なので、​それより​前の​状態は​ Time Machine などバックアップから、​その​日の​ファイルだけを​取り出して​戻せます。​保存先を​ iCloud Drive や​ Dropbox のような​同期フォルダに​している​場合は、​それぞれの​サービスが​持つバージョン履歴からも​戻せます。 The app’s own Undo (⌘Z) covers the edit you just made in that session. Since your files are plain Markdown, you can also restore an earlier state of a single day’s file from a backup such as Time Machine. If you keep your files in a synced folder like iCloud Drive or Dropbox, that service’s own version history is another way to recover a file.
